# 아키텍처

[English](architecture.md)

`exam-hwpx-kit`는 시험 영역의 결정과 HWPX 형식의 기계적인 처리를 분리합니다.

```text
ExamPaper 모델
 ├─ JSON Schema와 Pydantic 필드 검증
 ├─ 참조 관계와 중복 검사
 ├─ 상대 경로 자산 샌드박스
 └─ 보수적인 분리 방지 위험 추정
             │
             ▼
       도메인 렌더러
 ├─ 지문은 흐르는 문단으로 유지
 ├─ 문항 문단에 분리 방지 설정 부여
 ├─ 보기 상자는 짧은 1×1 표 사용
 └─ 그림과 단 설정은 python-hwpx API 사용
             │
             ▼
        HWPX 감사기
 ├─ 패키지·편집기 열림 안전 검사
 ├─ 공유 자원 ID 무결성
 ├─ 정규화한 원본 텍스트의 순서 비교
 ├─ 원본과 패키지의 이미지 해시 비교
 ├─ 단 설정 선언 비교
 └─ 개인정보를 최소화한 영수증
```

## 의존성 경계

이 패키지는 문서 생성, 쪽 설정, 문단 서식, 표, 그림, 저장, 패키지 검증, ID
무결성에 공개 `python-hwpx` API를 사용합니다. OWPML XML을 직접 만들거나
`python-hwpx` 소스를 복사하지 않습니다.

감사기는 선언된 단 수와 문서가 사용하는 이미지 참조를 관찰하기 위해서만 생성된 섹션
XML을 읽습니다. XML을 쓰거나 바꾸지 않습니다. 잘못되었거나 안전하지 않은 패키지
데이터는 처리되지 않은 예외로 드러나는 대신 실패한 감사 보고서가 됩니다.

## 실패 정책

검증은 실패 시 닫힘(fail-closed)입니다. 원본 보고서에 오류가 있으면 `render`는
시작하지 않습니다. 저장 후 파일을 다시 열어 감사합니다. 감사가 실패하면 새 출력을
지우고 성공 영수증을 돌려주지 않습니다.

사용하지 않는 자산 같은 경고는 생성을 막지 않습니다. 오류에는 CI 정책에 쓸 수 있는
고정된 코드가 있습니다.

## 지문을 표에 넣지 않는 이유

긴 지문은 단과 쪽을 넘어 자연스럽게 흘러야 합니다. 지문 전체를 1×1 표에 넣으면
나눌 수 없는 덩어리가 될 수 있습니다. 짧은 보기 상자만 1×1 표를 씁니다. 문항과
선택지는 문단 분리 방지 설정을 써서, 모든 내용을 표에 가두지 않고도 편집기에
명시적인 응집 힌트를 줍니다.
